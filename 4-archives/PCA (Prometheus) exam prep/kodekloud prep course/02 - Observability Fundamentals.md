
# Intro

_Observability_ - ability to understand and measure the state of a system based upon data generated by the system


helps:

- get insight into internal workings of a system/application
- speed up troubleshooting
- detect hard to catch problems
- monitor performance of an application

answers Whys:

- why errror rate is rising
- why is there high latency
- why are services timing out



Logs and Traces

- `traceId` - allows to follow operations as they traverses through components of the system

- individual events forming a trace are called _spans_ (oblouk, interval?)


Metrics

- a number giving us information about the state of the system
- e.g. CPU load, Number of open files, HTTP response time

- name, value, timestamp, dimension

- _Prometheus is all about Metrics (not logs or traces)_



# SLO/SLA/SLI


- give us goals to strive for
- e.g. "Application should have 97% uptime in 30 days rolling window"



SLI - Service Level Indicator

- e.g. Request latency, Error rate, Availability
- not all metrics make good SLIs, e.g. CPU usage
- good ones are those which user is impacted the most (e.g. Response Time, Error Rates)

SLO - Service Level Object

- _target_ value of range of an SLI
- SLI - Latency, SLO - Latency < 100ms

SLA - Service Level Agreement

- a contract between vendor and user
- $ fines
